# Бланк приёмки с участником

Статус: **пилот не проведён**. Пустые поля — места для будущего наблюдения, а не нулевые результаты. Использовать вместе с [матрицей ролей P, условий C и заданий T](../research/acceptance-personas.md). Источники популярности находятся [отдельно](../research/audience-popularity.md).

## Подготовка раунда

- Ответственный, дата, commit и URL сборки: …
- Вопрос раунда и выбранные T-ID: …
- Покрытие: какие цели посещения P и условия C нужны; что останется непроверенным: …
- Согласованный формат участия и заметок, доступ к записям и срок удаления: …
- Критерии решения, сформулированные до сеансов: …

Первый качественный раунд — ориентировочно 5–8 добровольцев, 2–3 задания каждому. Это проверка препятствий, а не репрезентативное измерение долей. Если важная роль или условие не представлены, их не отмечают пройденными. Участие несовершеннолетних требует отдельно подготовленного порядка согласия.

## Карточка сеанса

| Поле | Наблюдение |
| --- | --- |
| Случайный код | S…; без имени и контактов |
| Основная цель P / дополнительные условия C | … |
| Самоописание знакомства | Книги / Netflix / Tencent / несколько / ничего / не ответил; объём знакомства — по желанию |
| Язык и право на спойлеры | RU / zh-CN; вся трилогия допустима / избегать новых деталей |
| Устройство, браузер, способ ввода | … |
| Версия, T-ID, исходная ссылка | … |
| Предсказание до опыта | … |
| Наблюдаемое действие / препятствие | … |
| Помощь | Без помощи / навигационная / содержательная / не выполнено / отказ |
| Объяснение результата после опыта | … |
| Названное ограничение модели | … |
| Перенос на изменённое условие | Например, меньший треугольник или иной момент времени; … |
| Ожидание со слов участника после задания | … |
| Интерпретация команды | H подтверждена / опровергнута / недостаточно данных; почему … |
| Решение | Барьер / уточнение гипотезы / следующее наблюдение; issue … |

Ведущий даёт цель из T-ID без названий кнопок. Фактические слова и действия отделяются от интерпретации. Неожиданное поведение не означает отсутствие способностей у участника. Если человек отказывается от спойлера, предложить безопасное задание и записать «отказ», не «неуспех». **Текущий риск T03:** прямая ссылка и открытие опыта 03 сразу показывают сюжетный контекст; отметка в меню не гарантирует предупреждения до детали. Без согласия на сюжетные детали этот опыт не открывать; выбрать другой T. Это ограничение текущего продукта, не пройденная приёмка.

## Сводка раунда

| Задание | Покрытие P/C и N | Без помощи / с помощью / не выполнено / отказ | Объяснение наблюдения и ограничения | Препятствие → issue → повторная проверка |
| --- | --- | --- | --- | --- |
| T… | … | … | … | … |

Для объяснений хранить отдельные признаки: опора на наблюдение, правильность вывода и релевантность ограничения. «Частично» допустимо, если записано, что именно отсутствует. Два рецензента независимо читают заметки о содержательных ошибках; расхождения обсуждают и сохраняют. Счётчик правильных ответов и время выполнения не заменяют эту проверку.

Отчёт: `n из N наблюдавшихся участников выполнили T… без помощи на версии …`. Не переносить долю на всю аудиторию. Причину каждого затруднения проверять; не выводить её только из времени или количества кликов. Повторное объяснение после опыта показывает ближайшее понимание, но не долговременное усвоение или причинный эффект продукта. Для этого потребуется отдельное исследование.

Ошибку науки или блокирующую недоступность не усреднять с удачными сеансами. К каждой issue приложить безопасную ссылку состояния, шаги, ожидаемое/полученное, версию и T-ID. Не публиковать записи, контакты или идентифицирующие цитаты. Следующая проверка должна повторять затронутый путь и соседний сценарий, а не только подтверждать исправленный экран.
