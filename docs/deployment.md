# Развёртывание

## Рекомендованная площадка

Для текущего продукта подходит GitHub Pages: статические файлы, публичный репозиторий, нет backend или секретов. `base: './'` позволяет запуск под `/Geometry-System/`. Cloudflare Pages — альтернатива, если позже понадобятся заголовки доступа, previews каждой ветки и собственный домен. Для создания проекта Cloudflare требуется подключённый аккаунт; он не нужен для сборки или локального демо.

## Готовый артефакт

```sh
npm ci
npm run check
```

Результат: `dist/`. Проверки работают против этой production-сборки. Не подменять её содержимое файлами из другой ревизии.

## GitHub Pages

1. После проверки PR выбрать согласованный commit/ветку.
2. В Settings → Pages установить Source: GitHub Actions (однократная настройка владельцем).
3. Запустить `Deploy approved demo to GitHub Pages` вручную для выбранной ветки.
4. Workflow повторяет quality gate, загружает `dist/` и публикует в environment `github-pages`.
5. Проверить HTTPS-адрес из результата workflow: первый опыт, сферу 270°, запуск/паузу, обновление URL и источники. Ожидаемый адрес для данного репозитория: `https://mmkolpakov.github.io/Geometry-System/` — до проверки публикации это только ожидаемый адрес, не живое демо.

Workflow не запускает публикацию от каждого push: только явный `workflow_dispatch`. Основной CI проверяет PR и рабочую ветку без публикации. Приложение не собирает персональные данные и не отправляет события; хостинг при этом может вести собственные access logs.

## Откат

Повторно запустить deploy workflow для предыдущего принятого commit. Подтвердить версию в Actions и повторить smoke check. Прогресс браузера имеет отдельный ключ версии; не изменять схему без миграции.

## Ограничения готовности

Автоматические тесты и агентная приёмка не заменяют пилот со школьниками, преподавателем и человеком с исследовательским опытом. Перед широкой раскаткой провести сессии по протоколу `docs/research/product.md`. Наличие runbook не означает, что публикация уже выполнена.
